## 代码工具与改动自验

1. **改完必跑 syntax**：改完 `.rs` / `.kt` / `.py` 后跑 `python3 -m codekit syntax <文件路径>`；返回 FAIL 必须修完再交付，不允许「看着没问题」就交。这是**秒级单文件静态检查**，不属于「冒烟编译」，与 40-flow 的「自验按规模定档」并存——分档管的是构建/单测，不管这里。后端以 `python3 -c "from codekit.syntax import available_checkers; print(available_checkers())"` 实测为准：Rust 走 `rustfmt` 真解析器（只认语法错误，类型错误不误报）；Python 走 `ast.parse`（诊断标 `cpython`）；Kotlin 当前 `lexer-only`（装了 `ktlint` / `kotlinc` 会自动升级），词法层过了仍需编译或 `gradle` 兜底。
2. **改前查影响面**：改函数签名或公共 API 前，先跑 `python3 -m codekit callers <名字> .`，评估影响面再决定改几个文件。
3. **读代码先看结构**：要读陌生文件的结构，先 `python3 -m codekit symbols <路径>`，不要整文件 `readFile`（实测 2410 行 Kotlin 文件压成 127 条符号，19 倍压缩）。
4. **工具位置**：源码在 `~/workspace/codekit`，在工作区根目录可直接 `python3 -m codekit <子命令>` 调用；纯标准库、无第三方依赖。
5. **标准骨架与闸门**：`pyproject.toml` 已落在工作区根，**阻断级闸门是 `ruff check scripts/ codekit/ tools/`**（当前全绿），规则集只含 `F`（pyflakes 真 bug）+ `E9`（语法）+ `I`（导入顺序）。刻意**不**启用 `E4/E7`（一行多语句、分号、一行多导入）和 `format --check`——前者是本项目历史风格，后者会一次重排 33 个历史文件、把格式改动混进业务提交；这两项只对新写的文件做。`stocks-*` 历史目录存 267 个 F 错误，列为观察级逐步清，**不纳入阻断线**（红着的闸门等于没有闸门）。规则来源与「可判断 vs 必须强制」二分见 `~/.aharou/knowledge/external-catalogs/19-code-standards-templates.md`。**必须强制的事做成闸门，不写成祈使句**——文档里写「请不要提交 lint 错误」必然被违反。

## 编码纪律细则（自常驻片段外移，2026-11）
- 缩进跟随该文件现有风格；没有参照时用 4 个空格，不用 Tab。
- 只在系统边界（用户输入、外部 API）做校验，不为不可能发生的场景加兜底；不留向后兼容的临时手段。
- 评审自己的代码要换视角：不带着产生它的推理去审，对照需求与边界用例外报告影响正确性的缺口，风格类不发散、不顺带提抽象层。
- 不为让检查变绿而降标准：不改审计参数、不关规则、不降严重级、不换统计口径凑数字。动依赖、CI、接口契约或给出性能结论前，加载 `delivery-gates` 技能按档位跑闸门。
- 改一条规则或提示词之前，先确认这条规则的实际来源（哪个文件、哪个技能、哪层配置）——改错了层，下次仍会复发。

## 注释细则
- 只写「为什么这么写」：隐藏的约束、微妙的不变量、针对某个 bug 的绕行、令人意外的行为。不解释代码「做了什么」，不在注释里引用当前任务、改动或调用方。不留被注释掉的旧代码。

## 研究阻塞声明纪律（2026-11 第九轮蒸馏新增）
- **数据不可用时必须分层声明**，禁止笼统「无法研究/数据不够」：
  1. 哪些字段能核对（给出来源与校验结果）；
  2. 哪些字段缺失（给出具体缺失项和数量）；
  3. 能否限定比较范围（给出可行范围与样本数）。
- 每份外部数据建立固定 SHA-256 + 股票代码准入白名单，不整批接受也不整批拒绝；保留逐日来源标签（api/csv_legacy/cnfin），禁止混用。
- CRLF/LF 行尾格式差异在数据入口显式声明原始行尾格式，保留字节与哈希不变，不在代码里静默转换。
- 「研究验证未完成」是真实状态声明，不是可替代的交付物——用户要求「完成」时必须补代码或补实跑结果，不能只写一段文字说明。
